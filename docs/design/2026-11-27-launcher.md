# Riptide launcher

Approved 2026-11-27. The launcher is the first piece built, ahead of the build order in `2026-11-27-architecture.md`.

## What it is

One window: a banner, four tabs of settings, a line summarising the checks, and **Play** and **Quit**. Every setting lives in one file, `%APPDATA%\Riptide\riptide.toml`. The launcher writes it and the runtime reads it. Riptide has no environment variables and no command-line flags for settings.

## Decisions

- **L1. One settings file.** TOML, written atomically (temporary file, then rename). Keys left out keep their defaults. An unknown key is an error that names the key, so a typo is never silently ignored. A file that will not load is moved to `riptide.toml.bad` and the launcher starts from defaults, saying so.
- **L2. Three crates.**
  - `riptide-config` (library): the settings, defaults, range checks, load and save. No window code and no Windows calls.
  - `riptide-preflight` (library): facts about the machine (`gather`, Windows calls) and their judgement against the settings (`judge`, pure). The runtime will reuse it for D11.
  - `riptide-launcher` (program): the window. It edits a `Settings` value and calls the two libraries.
- **L3. Look.** Near-black and monochrome with hairline borders, in the manner of Linear and Vercel: a plain text header, underlined text tabs, settings on one bordered card, a white primary button. Custom-drawn with egui (`eframe` 0.37, OpenGL backend), using Windows' Segoe UI font when present. One executable, no web runtime, no game artwork.
- **L7. Background.** Slow pixel snow behind the whole window: flakes on a 2-point grid at four depths, with sway, a light wind, twinkle, and the cursor brushing them aside. It is drawn by the launcher's own code (`snow.rs`), is dim enough to read text over, and only moves while the window has focus.
- **L4. Tabs.**
  - **Game:** game folder (text field and Browse), console mode (Series X or Series S).
  - **Display:** monitor, resolution, window mode (fullscreen, borderless, windowed), HDR passthrough. Monitors and resolutions are read from Windows.
  - **Performance:** RAM budget and video-memory budget (automatic, or a number in GiB), what to do while a pipeline compiles (skip its draws, or wait), video-memory copies on or off, frame-time readout on or off.
  - **Checks:** each preflight check with its level (OK, warning, blocking) and a sentence of detail.
  - **Logs:** the session log (L8).
- **L5. Play.** Play saves the settings and runs the checks. A blocking check stops it and the Checks tab opens. Otherwise, if `riptide.exe` is beside the launcher it is started with `run --config <file> --log <session file>` and the launcher closes; if not, the launcher says the runtime is not installed yet and that the settings are saved.
- **L6. No Input tab** until Riptide has an input design.
- **L8. Logs.**
  - **One file per launcher session** in `%LOCALAPPDATA%\Riptide\logs\`, named by its start time; the newest 10 are kept. The runtime appends to the session file the launcher passes it, so one session reads top to bottom in one file.
  - **A line** is `2026-11-27T14:03:22.512Z WARN  launcher  message`: UTC time, level (`INFO`, `WARN`, `ERROR`), source (`launcher` or `runtime`), message. Text in any other format, such as a panic message, is still shown, as a plain line.
  - **The launcher logs** its start and the settings file used, a settings file that would not load or save, and each Play: every check with its level and detail, then the outcome.
  - **The runtime will log** a session header (graphics card, driver, RAM, settings), each unimplemented console function once, device loss and recovery, shader compiling, memory-budget pressure, frames over 100 ms with their cause, a crash location, and an end-of-session summary.
  - **Never logged:** game data and file contents.
  - **The tab** shows one session, this one by default. A picker reaches the older ones, because the launcher closes when a title starts and the log wanted afterwards is the previous session's. It has a filter (All, Warnings, Errors), Refresh, Copy and Open folder. Copy replaces the user's home folder with `%USERPROFILE%`.
  - **`riptide-log`** is its own library with no dependencies, so the runtime can use it without pulling in anything of the launcher's. A failed write is dropped: logging never stops the program.
  - The launcher does not log the runtime's exit code. It has closed by then; the runtime logs its own end.

## Checks in the first version

| Check | OK | Warning | Blocking |
| --- | --- | --- | --- |
| Game folder | chosen and exists | | not chosen, or missing |
| Free RAM | at least the RAM budget (automatic: 16 GiB) | less than the budget | less than half the budget |
| Page file room | at least 16 GiB of commit headroom | | less (the 14 GiB title block cannot be reserved) |
| Graphics card | a hardware adapter is found (shown with its driver version) | | none found |
| Power plan | not "Power saver" | "Power saver" | |
| Settings | all values in range | | a value out of range |
| Runtime | `riptide.exe` is beside the launcher | not installed yet | |
| Graphics driver | not older than the driver Riptide was last measured with, or nothing to compare | older than that driver | |
| Game's drive | an SSD with at least 2 GiB free | a hard disk, or less than 2 GiB free | |
| Antivirus | no real-time scanner is active | a real-time scanner is active | |

The last three were added on 2026-11-27 (S10).

- **Graphics driver** compares nothing until `docs/measurements.md` has its first entry; the measured version is the constant `MEASURED_DRIVER` in `riptide-preflight`. Versions of different makes of card are not compared.
- **Antivirus** asks Windows' Security Center which products have real-time scanning on. Windows shows a product's exclusions only to administrators, so the check cannot tell whether Riptide's cache folder is already excluded. It warns whenever a scanner is active and names the folder to exclude.

## Biggest risk

The settings describe a runtime that does not exist yet, so some will change. Each setting is one field in `riptide-config` and one widget in the launcher, so a change is small.
