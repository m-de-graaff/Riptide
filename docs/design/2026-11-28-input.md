# Input

Status: decided 2026-11-28, for issue #16. The first part is built (`riptide-hle`'s `input.rs`); what is not is marked.

## What was measured

The real title imports one function of the console's input library, `GameInput.dll`, by its number: `GameInputCreate`, number 1. Through the object it gets, in its first two minutes, it registers a device callback for gamepads and asks for the devices already there before the call returns, registers another for keyboards, and then reads the current gamepad reading every frame. It leaves its first screen when the gamepad's A button is pressed.

Windows has a library of the same name with the same interfaces. Passing the import through to it (what Riptide did before) gives the title the player's real controllers and nothing else.

## Decisions

- **I1. Riptide answers for the input library itself.** The title's input object, devices and readings are Riptide's. Passing through cannot give a title a controller when the player has a keyboard and a mouse, cannot apply bindings, and cannot be driven by a test. The cost is the interfaces' methods, which are built as titles need them; an unbuilt one names itself and stops the title, as everywhere.
- **I2. The title sees one gamepad, always connected.** It never arrives and never leaves, so a title is never stopped by its "reconnect your controller" screen because a pad's battery went. What the gamepad holds is everything held on any source at once: of buttons all that are down, of each axis the value further from rest.
- **I3. Sources: a controller, the keyboard, a script.** A real controller is read through XInput, the first one found. The keyboard is a gamepad while a window of the process is in front (table below). `RIPTIDE_INPUT_SCRIPT` holds buttons at times counted from the start of the run, for tests and measurements with nobody at the machine.
- **I4. Readings are taken when asked for.** There is no thread that polls. Each time a title asks, the sources are looked at, and a new reading is kept if anything changed; the last 256 are kept so that a title can walk them in order.
- **I5. Keyboard and mouse are mapped to the gamepad, not offered as devices.** Console titles are written for a gamepad; one that also reads a keyboard does so for text. The title's keyboard callback is registered and lists nothing. Not built: the mouse (as the right stick, with a sensitivity and a curve), and a keyboard device for titles that want text.
- **I6. Bindings live in `riptide.toml` under `[input]`.** Not built: today the table below is fixed. The launcher's Input tab (L6) edits that section: one row per gamepad control with the keys bound to it, the mouse settings, and a test pane that shows what the gamepad holds.

## The keyboard

| Gamepad | Keys |
| --- | --- |
| A, B, X, Y | Enter or Space, Backspace, F, R |
| Menu, View | Escape, Tab |
| Direction pad | the arrow keys |
| Left stick, and its button | W A S D, and C |
| Right stick, and its button | I J K L, and V |
| Shoulders | Q and E |
| Triggers | left Control and left Shift |

## What is not decided here

- More than one player.
- Controllers XInput does not report (PlayStation pads over HID), and trigger rumble.
- Whether focus should also gate the controller. Today a controller is read whether or not the window is in front.
